- 测试对象：`/mnt/e/agentguild/docs/evidence/v0.7a/stage2/iter2/deliverable/game/index.html`（单文件，未做任何修改，全程只读）

- 测试者立场：未参与制作，无代码审查前置（仅用 debug 钩子模拟"时间流逝/随机结果"，玩法本身全部真实操作）

## 裁决：不通过（有阻断性问题，不可上线）

**两个阻断性问题，第一个直接杀死游戏，第二个杀死唯一的自救途径。上一版被否的原因是"谁会要玩这个啊"——这一版的问题更严重：第 3 下点击之后游戏就死了，任何人都玩不下去。**

## 阻断性问题（玩不下去）

### 阻断 1：挖 3 块矿后矿层永久清空，游戏卡死（100% 复现，无 debug 钩子）

真实玩家路径复现（`playtest-blind.py` Section A1，无任何辅助）：

```
新手引导第1步「点击矿石，挖矿赚金币！」
连点 3 块矿石 → 金币 3，矿格 0
等 4 秒（远超 700ms 补矿间隔）→ 矿格仍为 0
刷新页面 → 矿格仍为 0（卡死是持久的）
```

根因（代码定位）：`completeOre()` 里**只有"假矿"分支会调用 `onLayerDepleted()`**（index.html:978-979），铜/铁/稀有矿正常挖完的分支（986-1018 行）从不调用。而第 1 层是无限层，唯一的补矿入口就是 `onLayerDepleted()` → `refillBatch()`（1087 行）。所以：

- 第 1 层（3 块铜矿）：挖完 3 块 → 永远空着，新手引导第 2 步"攒到 10 金币升级钻头"永远完不成（金币上限 3）；
- 第 2 层及以后（有限层）：最后一块矿若不是假矿（50% 概率），挖完 → 空场，既不出"矿脉枯竭"面板也不出"差一点"面板，**同样卡死**（Section A2 复现：最后一块=铜 → grid=0, panels=[]）。

上一版 e2e 全绿（54/54）是因为它只测了"最后一块是假矿"的路径（`forceNext('fake')`），正常路径从未被真实玩过——这正是盲测的价值。

### 阻断 2：「清空存档」按钮是坏的（唯一逃生通道失效）

卡死后唯一可能的自救是顶栏「↺ 清空存档」，实测：

```
点「清空存档」→ 确认框正常弹出并确认 → 页面确实刷新了
→ 存档还在（coins=3、层已空）→ 游戏依旧卡死
```

根因（代码定位 + 运行时验证）：`resetState()`（673 行）先 `localStorage.removeItem` 再 `location.reload()`，但页面注册了 `beforeunload → touchSeen → saveState`（1848、644-648 行），刷新瞬间把**内存里的旧状态重新写回存档**，removeItem 被立即覆盖。测试中确认：导航发生了、对话框被接受了、存档原样保留。玩家点击后看到"刷新了一下，什么都没变"。

> 结论：两个问题叠加 = 玩家从第 10 秒起被永久锁死，且没有逃生出口。

## 重要建议（按优先级，修复顺序）

1. **修 `completeOre()`：所有矿种完成分支都要在 `ores.length === 0` 时走 `onLayerDepleted()`**（无限层补矿 / 有限层弹枯竭面板）。这是 2 行级修复，但决定游戏能否运行。
2. **修 `resetState()` 与 `beforeunload` 保存的竞态**（重置标记或卸载时跳过保存）。
3. **假矿重roll的索引失效 bug**（核心记忆点上的坑，实测证实）：
   - `onFakeHit` 延迟 900ms 后才弹面板，但 `curFakeOreIdx` 是假矿**完成时**的旧索引；900ms 内玩家又挖掉几块，数组已缩短；
   - 实测（EDGE2）：重roll 会把**相邻矿石整个替换掉**（假矿在第 0 位，重roll后第 0 位变成了新矿，原第 1 位矿石凭空消失）；
   - 更糟：当层内矿石被挖到少于假矿旧索引时，`doReroll` 直接 `return`（1066 行），**重roll 静默失效**——免费的重roll没反应还好，广告重roll是"看完广告什么都没发生"（v7 会话实测踩中，广告面板从未出现、金币照扣）。修复：面板打开时按矿石 id 重新定位索引，且用"插入"而不是"替换"。
4. **离线收益名存实亡**（硬约束"长在线回访理由"不达标）：
   - 2 小时离线、矿工 1 级 → **+12 金币**（"离线效率 20%"）；8 小时封顶 = 48 金币，不到一轮挖矿的产出（一轮 35-52 次点击 ≈ 74-219 金币）。对比一次钻头升级 125+ 金币，离线基本是空气；
   - 根因：`rate` 是每秒产出，`cap` 是分钟数，`rate × coef × cap` 少了 ×60；
   - 新手（无矿工）离线回来**连结算面板都没有**（实测 EDGE1：2 小时离线 → 无任何反馈）。至少应给一个按矿场等级的兜底产出，让"明天回来"有明确收益。
5. **关键按钮触控尺寸不达标**（brief 明确要求 ≥44px）：
   - 底部 4 个导航 tab：81×35px（@320 时 67×35）
   - 排行 tab：145×33px；声音 39×33px；重置 26×32px；面板主按钮约 38px 高
   - 矿石格 62×62、升级卡 168×68 达标。差的都是高频入口，建议整体加 padding/字号。
6. **最后一块矿是假矿时，重roll机会被吞**：假矿恰好是最后一块 → 直接进"枯竭/差一点"面板，假矿重roll面板不再出现（`onFakeHit` 被 pause 状态吃掉）。与"重roll是核心记忆点"冲突——建议先给重roll机会，再结算枯竭。

## 打磨建议（不阻断）

- **"差一点"的触发太随机**：只有枯竭时距下次升级 ≤5 金币才弹"差一点"面板，我的两轮真实矿层都只遇到干巴巴的"矿脉枯竭→重开"。羊了个羊的"差一点"应该是稳定的节奏，建议把窗口放大并做成固定节拍。
- **分享文案**："我的第 X 天矿场刚开出稀有水晶，你的矿场还只有几座——但今天开始还不算晚。"——"几座"语病（矿场不按"座"计），且默认对方在玩；没开到稀有水晶时这句话也是假的。战绩卡数据本身（天数/等级/资产/净收益/收藏）是好的。
- 里程碑弹窗里的 `\n` 不会换行（textContent 无 `white-space:pre-line`），"深岩层 解锁限时稀有矿脉事件！"挤成一行。
- 假矿可以把金币扣成负数（显示 -1），建议下限 0。
- 第 1 层离线系数 0.5 不可达（矿工第 2 层才解锁），是死代码。
- 分享按钮"+20 金币"是贿赂式裂变，方向上 OK，但分享文案修好后才值得发。

## 两个裁决问题（诚实回答）

**明天会回来吗？—— 不会。** 就算修好阻断 1/2：离线 2 小时 = 12 金币（≈6% 一轮挖矿），"离线收益"这条硬约束不成立；中期断崖是"机械点 27 块石头"的枯燥，而不是"差一点"的懊恼（差一点面板随机且罕见）；唯一有记忆点的"最后一块 50% 假矿"有一半概率是正常矿（在修好前直接卡死，修好后也只是普通枯竭）。日任务/排行/矿脉事件都存在且达标，但撑不起"明天回来"的引力。

**会发给朋友吗？—— 不会。** 游戏在第 10 秒就死了，没有可炫耀的瞬间；战绩卡文案有病句、且默认对方在玩（他大概率没玩过）；+20 金币是贿赂不是炫耀。唯一可能成立的是稀有收藏（尤其钻石），但第一天极难拿到。

**一句话：设计骨架是对的（引导→爽快→断崖→假矿→广告→回访），但当前版本连"能玩"都不成立。修好阻断 1/2 + 离线 ×60 + 重roll 索引后，才值得做第二次盲测。**
