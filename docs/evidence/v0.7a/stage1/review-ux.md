## 三、交互链路与无障碍核验（预约按钮 → 弹窗 → 表单 → 校验 → 成功反馈）

交互链路完整可用：预约按钮（L578）→ 弹窗开启（L518-524）→ 表单三字段（姓名/电话/时间，L491-496）→ 校验（必填 + 11 位手机号正则，L535-550）→ 成功反馈（alert + 表单重置，L555-559）；含遮罩点击关闭（L563-568）、Escape 关闭（L571-575）、关闭后焦点归还触发按钮（L531）。

无障碍亮点：`role="dialog"` + `aria-modal="true"` + `aria-labelledby`（L486）、`aria-hidden` 状态切换（L516/520）、`aria-haspopup="dialog"`（L467）、按钮 `:focus-visible` 焦点样式（L409-414）、背景滚动锁定（L523）、表单 label 均有 `for` 关联（L491-496）。

### P2 中等问题（建议修复后上线）

| # | 问题 | 位置 | 影响 | 修复建议 |
|---|---|---|---|---|
| P2-1 | **按钮文字对比度不达标**：白字 on `#c97b4a` 实测 **3.27:1**，低于 WCAG AA 普通文字 4.5:1（按钮文字 17.6px/600，不属"大号文字"豁免），恰好落在**预约按钮（核心转化入口）和确认按钮**上 | L221-235（`.reserve-btn` background 与 color）、L319-328（`.btn-primary`）；色值 L24 `--accent: #c97b4a` | 约 5% 低视力用户辨识困难，属标准合规缺陷 | 将按钮底色加深至对比度 ≥4.5:1，如 `#a85f33`（实测可到 ~5.0:1），或改用深色文字+浅底；保留 `#c97b4a` 作为装饰色 |
| P2-2 | **表单反馈全部使用原生 `alert()`**：校验失败（L542/548）与成功反馈（L555）都是系统弹窗；无内联错误提示、无 `aria-invalid`/`aria-describedby`/`aria-live` 播报，错误时用户需自行推断哪个字段有问题；成功 alert 在弹窗关闭后弹出，移动端体验割裂 | L541-559 | 反馈不落地在表单上下文中，无障碍与体验双输 | 弹窗内增加错误提示行（`role="alert"` 或 `aria-live="polite"`）；输入框错误态（红边 + `aria-invalid`）；成功时改为弹窗内成功态（如 ✓ 图标 + 文案）而非 alert |
| P2-3 | **弹窗无焦点陷阱**（WAI-ARIA dialog 模式要求 Tab 循环于弹窗内）：Tab 可从弹窗最后按钮移出到浏览器 UI，Shift+Tab 会回到背景的「预约到店」按钮（遮罩下层）；且打开时焦点落在**「稍后再说」按钮**而非第一个输入框（L522），与常见键盘用户预期相反 | L518-524、弹窗 DOM L486-503 | 键盘/读屏用户会"走丢"，读屏读出被遮罩背景元素 | openModal 时聚焦第一个输入框（`guestName`）；添加 Tab 循环：监听弹窗内 `keydown`，焦点在首/末元素时回环 |
| P2-4 | **`.form-fields` 无任何 CSS**：搜索样式表无 `.form-fields` 规则（仅 HTML L490 使用），导致输入框不撑满弹窗宽度（默认 ~170-200px 左对齐）、label 与 input 之间无间距、输入框高度约 30px 低于 44px 触控推荐值——表单区是全页排版完成度最低的区域 | L490-497（HTML）、样式表缺失 | 核心转化表单观感粗糙、移动端触控吃力 | 补充 `.form-fields` 样式：纵向 gap（如 8px label / 12px 字段间距）、`input { width:100%; padding:12px; font-size:16px; border-radius; }`，使高度 ≥44px |

### P3 改进建议（不阻断，按性价比排序）

| # | 问题 | 位置 | 建议 |
|---|---|---|---|
| P3-5 | 表单无 `<form>` 包裹、无 `name`/`autocomplete`/`required` 属性，移动端回车键/键盘"完成"无法提交，浏览器无自动填充 | L490-497 | 用 `<form>` 包裹，`onsubmit` 接现有校验逻辑；补 `autocomplete="name"`/`autocomplete="tel"` |
| P3-6 | 门店区 `aria-labelledby` 指向的 `#shop-heading` 是**普通 div 而非标题元素**（L459-460），读屏将整块文本（地址+时间+按钮文案）作为区名；且该区是全页唯一无 `<h2>` 的 section，标题层级断裂（h1→h3） | L459-461 | 增加 `<h2>` 标题（如「到店信息」）并将 `aria-labelledby` 指向它 |
| P3-7 | 装饰性 ☕（opacity 0.2）无 `aria-hidden="true"`，读屏会播报"咖啡"表情 | L471 | 加 `aria-hidden="true"` |
| P3-8 | 无 `<main>` landmark，页面内容直接挂 body 下 | L417-585 | 用 `<main>` 包裹主体各区 |
| P3-9 | 中文衬线意图落空：`--font-serif: Georgia...`（L46）不含中文字形，中文标题实际回退系统黑体，设计意图（宋体/衬线质感）在中文场景不生效 | L46、L102 | 引入中文字体栈（如 `"Noto Serif SC", "Songti SC", serif`）或按品牌调性选一款中文宋体 |
| P3-10 | `viewport-fit=cover` 无 `env(safe-area-inset-*)` 内边距，刘海屏横屏/底部 Home 条可能遮挡内容 | L5 | 容器 padding 叠加 `env(safe-area-inset-left/right)` |
| P3-11 | 全页无任何实景图片/照片（Hero 为纯色渐变）——需求未要求，但作为独立咖啡品牌落地页，实景图是氛围与信任感的主要载体 | L72-91 | 后续迭代可补咖啡/门店实拍图（需注意 alt 文案） |
| P3-12 | 代码卫生：L522 注释重复两行；L516 与 HTML 静态属性重复设置 `aria-hidden` | L516-522 | 清理冗余（低优先级） |
