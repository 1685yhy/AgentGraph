# AgentGuild 使用指南——写给产品经理

> 你好，我是闫海洋。这篇指南是专门为你写的。你不需要会写代码，不需要懂技术术语，你只需要会用 Claude Code。

---

## 一、这是什么

**AgentGuild 是一群有自己性格、有自己立场、甚至还跟你抬杠的 AI 专家。**

你可以把他们想象成你团队里的不同角色——有产品经理、有前端工程师、有设计师、有用户研究员——但他们不是真人，而是住在你电脑里的 AI Agent。每个 Agent 都有自己的专业领域、自己的"信仰"、甚至知道自己不擅长什么。

你不需要跟他们客套。直接说"帮我写个 PRD"，你团队里的 PM Agent 就会开始干活。

---

## 二、我能用它做什么

以下是几个你马上就能用的场景：

### 场景 1：让 PM Agent 帮你写 PRD

你有一个新功能的想法，但不想从空白页开始。叫出 PM Agent，告诉它你的想法，它就会给你一版结构完整的 PRD——包含问题定义、成功指标、用户故事、范围边界、回滚计划。你不是一个人在写文档。

### 场景 2：让 PM + 前端 + 后端 三个 Agent 一起评审需求

你写完 PRD 草稿后，让前端 Agent 评估可行性，后端 Agent 评估工作量，PM Agent 检查范围是否合理。三个 Agent 会从各自的角度给出反馈，甚至互相争论——这种争论恰好能帮你提前发现风险。

### 场景 3：让 UX Researcher 帮你想用户研究的方案

你要做用户访谈但不知道问什么、不知道找多少人、不知道用什么方法。叫出 UX Researcher Agent，告诉它你的产品场景，它就能给你一个完整的研究方案：样本量、招募标准、访谈提纲、分析方法。

### 场景 4：让一群 Agent 组队完成一次完整的产品迭代

从用户研究 → 写 PRD → 设计评审 → 技术评审 → 写技术文档，整个流程可以交给不同的 Agent 接力完成。你只需要在每个环节检查结果、做决策。

## 三、怎么安装

前提是你已经安装了 **Claude Code**。如果你还没装，先装好它。

然后打开终端（Terminal），复制粘贴下面两行命令，回车执行：

```bash
cd /mnt/e/agentguild
./scripts/install.sh --tool claude-code
```

就这么简单。执行完后，你的 Claude Code 就知道了全部 12 个 Agent 的存在。

> 如果你是用 Cursor、GitHub Copilot 或 Windsurf，把最后面的 `claude-code` 换成对应的工具名就行。

安装完可以验证一下——随便打开 Claude Code，输入 `/help`，你应该能看到系统提示里出现了 AgentGuild 相关的信息。

## 四、怎么激活单个 Agent

在 Claude Code 里，你直接**说出 Agent 的名字**，它就会被激活。就这么简单。

### 示例对话 1：叫 PM Agent 干活

```
你：@产品经理 帮我写一个用户积分系统的 PRD

Claude Code 会以 PM Agent 的身份回复你，给你一份结构完整的 PRD 文档。
```

### 示例对话 2：叫用户研究员干活

```
你：@用户研究员 我们想做一个新的学习打卡功能，用户是中小学生，帮我设计一个用户研究方案
```

### 示例对话 3：叫前端工程师干活

```
你：@前端工程师 评估一下这个 PRD 里的功能，从技术角度看哪些实现起来比较困难
```

每个 Agent 都会用自己的"性格"回复你——PM Agent 会强调目标和指标，前端 Agent 会关注性能和实现成本，UX Researcher 会质疑你的假设。这种风格差异不是 bug，是 feature。

## 五、怎么组队——让多个 Agent 配合

真正的产品工作很少是单打独斗。AgentGuild 最强大的地方在于，你可以让多个 Agent 在一个会话里轮流干活，像真人团队一样配合。

### 完整示例：PM 写完 PRD → 找前端和后端评审 → 让 QA 检查

**第一步：PM Agent 写 PRD**

```
你：@产品经理 我们想做一个学习成就徽章系统，用户完成课程后获得徽章，可以展示在个人主页上。
帮我写一个 PRD，包含问题定义、成功指标、用户故事和范围边界。
```

PM Agent 会输出一份 PRD。你检查一下，觉得 ok。

**第二步：叫前端和后端一起评审**

```
你：@前端工程师 @后端架构师 刚才的 PRD 你们看一下，从技术角度评估一下可行性和工作量。
前端：UI 实现上有没有难度？
后端：数据存储和接口设计上有什么建议？
```

前端 Agent 和后端 Agent 会各自给出反馈。他们可能会对 PRD 里的某些假设提出质疑——这是好事，说明他们在认真工作。

**第三步：叫 QA 兜底检查**

```
你：刚才 PM 写了 PRD，前端和后端也评审完了。现在帮我检查一下：
有没有技术方案和 PRD 要求对不上的地方？
有没有遗漏的边界情况？
```

（这里你可以直接让 Claude Code 综合所有信息回复你，不需要再指定 Agent，因为前面对话的上下文都在。）

---

### 进阶技巧：在一个消息里召唤多个 Agent

```
你：@产品经理 帮我写一个打卡提醒功能的 PRD，功能是用户设定每天的学习目标，
到期未完成时推送提醒。写完后 @前端工程师 和 @后端架构师 分别给一份技术评审意见。
最后 @用户研究员 判断一下这个功能的核心假设是什么，建议用什么方法验证。
```

Claude Code 会按顺序执行：先写 PRD → 前端评审 → 后端评审 → 用户研究员验证假设。一个消息搞定整个流程。

## 六、常用 Agent 组合

以下是三个最常用的团队组合，你可以直接复制使用。

### 场景 1：从零启动一个功能

**适合：** 你有一个功能想法，但需要把它变成一个可执行的产品方案。

**推荐组合：** `@产品经理` + `@用户研究员` + `@技术文档工程师`

**你可以这样说：**

```
我们想做"学习小组"功能，让用户可以组建学习小组、互相监督打卡。
帮我走一遍完整的产品启动流程：

@用户研究员 我先需要你帮忙设计一个用户研究方案——我们想了解用户
在学习打卡过程中哪些地方坚持不下去，什么情况下会放弃。
输出研究方法和访谈提纲。

@产品经理 等用户研究有结果后，你基于研究发现写一份 PRD，
包含问题定义、成功指标、用户故事、MVP 范围。

@技术文档工程师 PRD 定稿后，你写一份产品功能介绍文档，
面向内部团队，描述这个功能要做什么、不做什么。
```

### 场景 2：评审技术方案

**适合：** 技术团队出了一个方案，你需要从多个角度验证它是否靠谱。

**推荐组合：** `@前端工程师` + `@后端架构师` + `@DevOps 工程师`

**你可以这样说：**

```
我们技术团队出了一个"积分系统的架构方案"，我需要你们评审一下：

@后端架构师 检查 API 设计、数据模型、认证方案有没有问题。
@前端工程师 看看 UI 层有没有性能隐患，加载方案是否合理。
@DevOps 工程师 评估部署方案、监控告警和扩容策略是否完整。
```

### 场景 3：设计评审

**适合：** 设计师完成了 UI 稿，你需要确保设计质量。

**推荐组合：** `@UI 设计师` + `@创意指导` + `@品牌守护者`

**你可以这样说：**

```
我们新功能的 UI 设计稿做好了，需要设计评审：

@UI 设计师 从视觉设计系统的角度审查所有页面——
布局、颜色、字体、组件一致性。
@创意指导 从整体美学方向给意见——这套设计有辨识度吗？
@品牌守护者 检查是否跟我们的品牌规范一致——
色彩、调性、视觉标识有没有偏离。
```

## 七、怎么自己写 Agent

AgentGuild 不只是别人给你写好的 Agent，你也可以自己写。你只需要复制一个模板，改几个地方就行。

### 第一步：找到模板

在 `/mnt/e/agentguild/docs/AGENT_TEMPLATE_zh-CN.md` 里，有一份完整的中文模板。

### 第二步：复制 + 改名字和描述

打开 Agent 模板，你会看到这样的结构：

```yaml
---
name: 你的 Agent 英文名
short: 你的 Agent 中文名
role: 所属部门（engineering / product / design）
description: 一句话描述，160 字以内
---
```

把这几项改成你自己的 Agent。

### 第三步：写你的"挑衅性观点"

这是 AgentGuild 的灵魂。每个 Agent 都要有一个**有态度的专业立场**——就是你在这个领域最想说的那句狠话。

举个例子：

- **平庸的模板：** "我认为用户体验很重要。"
- **有态度的 Agent：** "大多数产品死在功能太多而不是太少。每加一个功能，你就稀释了核心体验一次。"

看到了吗？挑衅性观点不是骂人，是**有依据地反对主流共识**。

### 最简版本——直接复制这个结构

```yaml
---
name: Localization Manager
short: 本地化经理
role: product
description: 负责产品多语言策略、翻译质量管理与全球化适配。
---

## 1. 身份与记忆

[写 3-5 句话：你是谁，你经历过什么，什么塑造了你的判断力]

## 2. 核心任务

[你的工作范围，写 3-5 个具体能力领域]

## 3. 挑衅性观点

[你在这个领域坚持的一个非主流信念。至少 3 句话。]

## 4. 铁律

[你绝不妥协的 3-5 条原则]

## 剩下的段落

技术交付物、工作流程、沟通风格、成功指标、冲突偏好、
盲区声明、决策权重、协作契约。

[参考模板补全即可]
```

### 写完后怎么用

把写好的 `.md` 文件放到对应的部门目录下：

```
agents/
├── product/    ← 你新写的 Agent 放这里
├── engineering/
└── design/
```

然后运行 `./scripts/install.sh --tool claude-code`，你的新 Agent 就上线了。下次在 Claude Code 里 @它，它就会以你设定的人格回复。

## 写在最后

AgentGuild 的核心思想是：**给你的 AI 工具装上真正的"人"，而不是万能的工具。**

每个 Agent 有专长、有盲区、有自己的脾气。这恰恰让他们之间的配合更真实、更有价值。

你不用一次学会所有东西。先从最常用的场景开始：
1. 装好 Agent
2. 叫 PM Agent 写一个 PRD
3. 叫前端和后端评审一下

跑通一次，你就知道怎么用了。

剩下的，慢慢来。
