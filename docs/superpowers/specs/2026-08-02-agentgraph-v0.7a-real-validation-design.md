# AgentGraph v0.7a — 真实 LLM 端到端验证

**日期**: 2026-08-02
**版本**: v0.7.0-alpha
**状态**: 设计完成，待实现
**前置**: v0.6a 运行时引擎（commit 6abbca6）已完成并推送

---

## 1. 背景与目标

v0.3~v0.6a 已完成：18 类型分类器、18 模板脚手架、23 个 MCP Tools、自建运行时引擎。但端到端测试使用的是 **mock LLM**——系统能跑通链路，尚未用真实大模型交付过完整产品。

**目标**：证明 AgentGraph 用真实 LLM 能端到端交付一个"用户不用改"的完整产品，并把链路暴露的所有缺陷整理成 backlog，作为 v0.7c（系统鲁棒性）的输入。

---

## 2. 成功标准

| # | 标准 | 判定方式 |
|---|------|---------|
| 1 | 小任务（落地页）交付，无阻断性缺陷 | Gate 全过 + 独立审查通过 |
| 2 | 中任务分类正确（置信度 ≥0.8）、计划被批准 | classify/plan 输出 + 用户审阅 |
| 3 | 中任务交付物过全部 Gate + 独立审查 | 审查报告 |
| 4 | 修复回路闭环（有缺陷则自动修自动验） | 修复记录 |
| 5 | 每步有证据报告（日志/Gate/审查） | `docs/evidence/v0.7a/` 报告文件 |
| 6 | 缺陷清单进 backlog | backlog 文档 |
| 7 | 成本可控（DeepSeek，中任务修复循环最多 5 轮） | 花费记录 |

## 3. 执行流程（三阶段）

### 阶段 1：点亮链路（小任务 · 落地页）

1. 配置真实 LLM（见 §4）
2. 起草落地页需求 → 用户确认
3. `guild run --graph feature-dev --task "<需求>"` → 真实执行
4. Gate 检查 → 独立审查 → 证据报告

### 阶段 2：质量闭环（中任务 · 系统自选）

1. 用户出一个真实业务需求（一句话即可）
2. 系统 classify → 展示置信度 → 用户确认或换题
3. 系统 generate_plan → 用户审计划 → 批准/调整
4. 全链路真实执行 → Gate → 独立审查
5. 有缺陷 → 修复回路：自动生成 fix 任务 → Agent 修 → 重跑 Gate → **最多 5 轮** → 人工判定兜底
6. 最终交付 + 证据报告

### 阶段 3：复盘

把两步暴露的缺陷/改进点整理成 `docs/superpowers/specs/backlog-v0.7c.md`，作为 v0.7c 输入。

## 5. 错误处理

| 场景 | 处理 |
|------|------|
| LLM 调用失败/超时 | llm-backend 重试 3 次 + 指数退避；仍失败则记录并停在该节点 |
| Agent 输出为空/JSON 解析失败 | 自动重试 1 次 → 仍失败记录缺陷，继续下一节点 |
| Gate 不通过 | 中任务启用修复回路；小任务先记录（链路优先） |
| 中途断电/中断 | 不做大改造（v0.7c 范围），记录断点位置，手工续跑 |
| 分类置信度 <0.8 | 暂停并列出候选类型，用户选择 |

## 6. 测试与验证

- 每阶段前后跑 `bash scripts/self-test.sh`，18/18 无回归
- 独立审查：审查 agent 使用与执行不同的角色盲审（如执行是 frontend-engineer，审查派 ux-researcher + qa-engineer）
- 证据报告落盘：`docs/evidence/v0.7a/`（运行日志、Gate 输出、审查报告、修复记录）
- 用户最终验收两件交付物，确认"用户不用改"是否达成
