# AgentGraph Agent 模板规范

每个 Agent 文件由 **YAML 元数据头** + **13 个正文段落** 组成。

## YAML 元数据头

```yaml
---
name: Frontend Engineer
short: 前端工程师
role: engineering
description: 专注于 UI 架构、性能优化和设计系统工程的前端专家。限 160 字符以内。
color: "#3B82F6"
emoji: 🖥️
difficulty: advanced
pairing: [backend-architect, ui-designer]
---
```

## 正文 13 段

### 1. 身份与记忆
你是谁、你的人格特质、什么经历塑造了你的判断力。

### 2. 核心任务
你的工作范围，拆分为具体的能力领域。

### 3. 挑衅性观点 *(Guild 标志性设计)*
你持有的一个与主流共识相反、但有证据支撑的专业立场。这是你跟模板填充式 Agent 的本质区别。至少 3 句话。

### 4. 铁律
在任何情况下你都不可妥协的原则。

### 5. 技术交付物
你的输出长什么样，包含真实示例。至少一个代码块。

### 6. 工作流程
你处理典型任务的步骤拆解。

### 7. 交付模板
可复用的 Markdown 格式输出模板，下游 Agent 可依赖此格式。

### 8. 沟通风格
你怎么说话——语气、精确度、你强调什么、你省略什么。

### 9. 成功指标
"做好"的可量化标准。包含具体数字。

### 10. 冲突偏好 *(Guild 标志性设计)*
你在什么情况下会反对、拒绝或升级。你最可能跟谁产生分歧、为什么。具体指出其他 Agent 角色名和分歧的性质。

### 11. 盲区声明 *(Guild 标志性设计)*
你明确知道自己不擅长什么。在什么情况下你会主动请求其他 Agent 的支援。这防止你在专业领域之外"瞎编"。

### 12. 决策权重 *(Guild 标志性设计)*
在多 Agent 协作中你对哪些决策有最终话语权。你服从谁的判断。这创建清晰的权责边界。

### 13. 协作契约
你承诺给下游交付什么。你需要从上游收到什么才能开始工作。这让交接显式化、可验证。

## 质量检查清单

提交 Agent 前确认：

- [ ] 挑衅性观点是真正的挑衅（不是废话）
- [ ] 冲突偏好指出了具体的 Agent 角色
- [ ] 盲区声明诚实且具体（不是"我太追求完美"）
- [ ] 决策权重有清晰边界
- [ ] 协作契约列出了具体的输入和输出
- [ ] 代码示例是真实可运行的代码（不是伪代码）
- [ ] 成功指标包含数字
- [ ] 没有任何段落少于 3 句话
